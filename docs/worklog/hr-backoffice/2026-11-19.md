- 왼쪽 메뉴: 백오피스 묶음 모양(굵은 묶음 이름 + 사람 아이콘, 들여 쓴 하위 메뉴, 선택 민트 막대, 폭 w-60). 묶음이 하나라 늘 펼침.

- 직원 목록: 미리보기 칸(줄 누르면 오른쪽 요약, ↑↓·Esc, 사번 링크는 상세, 상세와 같은 조회 키), 내 보기(상태·소속만 저장 — 검색어 = 이름은 저장 안 함, 키 `pmart.hr-backoffice.views.*`).
- 시험 3개. 확인: typecheck·lint·test(11파일 73개)·build:lan 통과. 화면 확인은 개발 서버가 필요해 사용자에게 켜 달라고 부탁(백그라운드로 켜지 않음).

## 인사팀 화면 보충 — "백오피스보다 심심하다"(브랜치 hr-backoffice/richer)
- 사용자: "인사팀 쪽은 백오피스 쪽보다 너무 심심한 느낌" → 추천 5개 "다 진행 해".
- 1 직원 상세 계정 발급 진행 단계(요청·사서함·로그인 계정·안내 메일·완료). 실패·되돌림은 계약에 "어느 단계에서" 가 없어 단계를 칠하지 않고 갈래로만. `ProgressSteps` 는 백오피스 사본.
- 2 직원 상세 "다음 할 일" — 서버 값만으로 하나(발급 실패 → 정지 → 발급 중 → 권한 승인 대기). 단추는 같은 쪽의 계정 발급·인사 처리 구역으로 옮겨 갈 뿐, 명령은 그 구역 단추로.
- 3 종류 꼬리표(`KindChip`) — 고용 형태·소속 아이콘(목록·상세), 요청 권한 역할 꼬리표, 승인 상태 색(`submissionTone`).
- 4 구역 제목 아이콘(`TitleIcon`, 상세·등록·권한 관리) + 등록 화면 흐름 줄(정보 넣기 → 권한 요청 → 계정 발급).
- 5 첫 화면(`/`, 전에는 직원 목록으로 바로 넘김) — 바로 가기 4개, 상태별 목록(`?status=`), 등록 흐름 설명. **인원 숫자·최근 등록은 넣지 않음**: 세는 조회는 H-D2 대기, 직원 목록 정렬은 계약에 없다.
- 확인: typecheck·lint·test(12파일 75개)·build 통과. 화면(5174 목, 직접 조작): 첫 화면 바로 가기·상태 목록, 목록 꼬리표 아이콘, 발급 실패 직원(다음 할 일·실패 갈래·"계정 발급으로" 이동), 정지 직원(다음 할 일·단계 5개 완료), 등록 흐름 줄·제목 아이콘.
- 6 메뉴 접기(사용자 "인사팀은 왜 메뉴 바를 접는 옵션이 없어?" — 백오피스 #171 에만 넣고 인사팀 사본을 빠뜨렸다). `sideMenu.ts` 사본(기억 키 `pmart.hr-backoffice.menu`, 1280px 보다 좁으면 접어서 시작). 접으면 64px — 묶음이 "인사" 하나라 묶음 아이콘 대신 **메뉴 다섯 개를 각각 아이콘**으로. 시험 환경 폭 1440·기억 지우기. 확인: 시험 76개·build, 화면(접기 64px·아이콘 5개·지금 화면 강조·아이콘으로 권한 관리 이동·다시 펴기·기억 open).
