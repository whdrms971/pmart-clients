## 메뉴 알림 — 묶음 합계를 색별로(브랜치 backoffice/menu-alert-counts)
- 사용자: "지원센터에서 메뉴를 펼치기 전엔 7 인데 펼치면 8 개고 접었을 때 빨간색 알림만 보이는데 해결해".

## 쿠팡 윙 레퍼런스 패턴 전부(브랜치 backoffice/wing-patterns, #224 위)
- 사용자 "레퍼런스만 참고해서 전부 적용". 정리한 8가지:
  1. 실시간 배송 두 줄 카드 — "먼저 확인하고 처리해 주세요"(약속 시간 지남·전달 실패 등록·라이더 미배정·처리 중 접수 건, 누르면 그 배송만 focus=/state=) + "배송 진행 단계"(미배정›배정›점포 도착›픽업›고객 도착, 누르면 그 상태). 카드 숫자는 상태 거르기 없는 같은 조회(캐시 공유), "이 화면에 읽어 온 N건 기준".
  2. 할 일 0건 "수고하셨어요" 띠(`AllDone`) — 접수 건(처리 끝남 탭 빼고)·승인함 심사 대기·처리 대기·문의 미답변. 서버 성공 0건일 때만, 처리 대기는 잘림·못 읽은 원천·MFC 꺼짐이 없을 때만(시험이 잡음). 빈 안내와 겹치지 않게.
  3. 검색 조건 칩 — `SearchPanel summary`: 조건을 건 뒤엔 "🔍 검색 조건 [종류 취소▾][상태 …▾] … 검색 열기" 한 줄로 접힘, 조건이 없으면 펼침. 클레임·배송 조회·라이더 컴플레인. 시스템 ID 조건은 "한 주문/한 라이더".
  4. 상품 등록 "어떤 방식으로 등록하시겠어요?" 큰 카드 4개 — 직접 입력·상품 JSON 으로 채우기(폼 안 파일 칸으로)·일괄 등록·같은 기초상품으로(상품 고르면 ?sameBaseAs=).
  5. 카드형 목록 — 교대 인계 목록이 이미 카드(위 띠·항목·단추)라 그대로. 접수 건은 칸을 견줘 보는 표가 맞아 표로 둠.
  6. 대시보드 "조치가 필요한 항목" — 이미 "내 할 일" 아이콘 숫자 줄(기한 지남·안 맡음·처리 대기·문의·승인)이 같은 역할이라 그대로.
  7. 일괄 행동 줄 — 접수 건 목록 "N개 선택됨 [선택한 건 내가 맡기]"(맡을 수 있는 줄만 체크). 계약에 일괄 명령이 없어 건마다 다시 읽은 version·각자 Idempotency-Key 로 하나씩, 실패한 것만 같은 키로 다시. 결과는 서버 응답대로 "N건 맡았어요 · M건 못 맡음".
  8. 카드마다 "최근 HH:MM ⟳" — 대시보드 머리 "방금 갱신 · 1분마다 자동 · 지금 새로 고침"이 이미 같은 역할이라 그대로.

- 이어서(사용자 "배경 전처럼 회색, 상품 조회 이름순 작동 안 함, 참고 고치기"):

## 콘텐츠 조회·상품 사진(브랜치 backoffice/content-lookup, #231 위)
- 사용자 "콘텐츠 조회 기능이 추가됐으면, 상품 조회 안에서도 사진이 보이게".

- 이어서(사용자 "걍 지금 바로 고쳐"): 상품 상세 시스템 ID — 제목 "사과 1.5kg 상품 P-…" → 이름만, 상품·기초상품·대표 카테고리·승인 ID 는 "시스템 번호" 접기로. 상품 요약 대표·노출 카테고리 노드 ID → 경로(트리 queryKey 공유, 못 읽으면 "?"), 승인 apv-… → "승인 보기 ›"(이름표 "건" → "승인"). 새 시험 1개(시스템 번호 접기 밖에 ID 없음), 백오피스 611개 통과, 화면 캡처 확인.

## 일괄 등록 — 파일 한 번 올리기(브랜치 backoffice/import-once, #245 위)
- 사용자 "콘텐츠 일괄 등록이랑 상품 일괄 등록이 같잖아" → 추천안(올리기 한 번, 제출·승인은 따로) "그렇게 만들어".
- 근거(계약): 세 일괄 등록이 모두 같은 seed-v1.zip 을 받고 서비스마다 다른 부분만 읽는다 — product `POST /product-import-batches`(product·skus 만, "이미지·content 는 product-content-service 가 같은 묶음을 따로 받는다"), content `POST /content-import-batches`(content·images/ 만, seedProductId 로 upsert·다시 올려도 안 늘어남, 상품 발행 때 같은 원천 키로 연결), pricing `POST /price-import-batches`(승인 전 새 상품은 SKU_NOT_FOUND, 승인 뒤 "다시 대조").
- /imports: 보낼 곳(상품·콘텐츠·가격, 기본 셋 다) + 올리기 칸 하나 → 서비스마다 따로(다른 Idempotency-Key, 요청마다 파일 사본) → 결과 카드 셋(요약·다음 할 일·배치 열기). 거절은 그 카드만 "이것만 다시 보내기"(새 키), 불명은 같은 키로 결과 확인. 가격의 SKU 없음은 오류 대신 "상품 승인 뒤 다시 대조" 안내. 탭 셋은 없앰, 옛 주소·배치 화면은 그대로.
- 시험: 셋 따로·키 셋, 가격 빼기, 하나 거절. 가격 목은 Node 시험 환경에서 업로드 본문을 읽다 끊겨(브라우저 목 모드는 정상) 이 시험은 가격 응답을 계약 모양으로 정해 둠.
- 확인: typecheck·lint·build·test(619개) 통과. 화면에서 zip 을 골라 올려 카드 셋 확인(상품 3·정상 2·오류 1 / 콘텐츠 2·사진 2 / 가격 3줄·SKU 없음 1).
- 고침(사용자 "이렇게만 나오고 다음 진행 같은 건 할 수가 없는 거 아님?"): 결과가 화면 안에만 있어 배치 화면에 갔다 오면 사라졌고, 올린 순간의 결과만 보였다. → "진행 현황": 배치 번호를 주소(?product=&content=&price=)에 남기고, 카드마다 배치를 다시 읽어(배치 화면과 같은 queryKey, 창에 돌아오면 새로 읽음) 서버 상태 배지(검사 끝·제출 전 / 승인 기다리는 중 / 반영됨·게시됨 / 반려됨)와 "다음:" 할 일, 단추(제출하러 가기·다시 대조하러 가기·배치 열기). 콘텐츠·가격은 같은 화면의 상품 배치가 반영됐는지 보고 안내(막지 않음, 판정은 서버). 상태를 못 읽으면 "읽지 못했어요"+다시 읽기. 목 모드는 zip 내용을 읽지 않아 늘 같은 시험 숫자임(실서버는 파일대로). test 625개 통과, 화면(올리기 → 제출하러 가기 → 뒤로, 카드 남음) 확인.

## 상품 하나씩 등록 다듬기(브랜치 backoffice/product-unfinished, #253 위)
- 사용자 "이어서 해"(추천안 A — 차례대로 등록을 잊지 않게).
- 상품 목록: "판매가" 거르기(전체·미설정만, 주소 price=notSet — 서버 notSet 기준, 못 읽은 상품은 거르지 않고 남김). 표 위 "등록이 덜 된 상품" 띠 — 사진·설명 없음 N(게시 카드 missing)·가격 미설정 N(SKU 가격 notSet), 불러온 쪽 기준·다음 쪽 있으면 "+", 못 읽으면 "?"(0 아님), 누르면 그것만 거름. 둘 다 0 이면 띠 없음.
- 상품 상세: 맨 위 다음 할 일 "등록이 덜 끝났어요" — 게시 콘텐츠 없음(404 NOT_FOUND·CONTENT_NOT_PUBLISHED)이면 "사진·설명 등록"(그 상품으로), 가격 미설정 SKU 가 있으면 "가격 정하기"(그 SKU). 못 읽으면 말하지 않음.
- 메뉴·홈 알림은 넣지 않음: 상품마다 가격을 알려면 상품 상세를 하나씩 읽어야 해(GET /products/{id} → /prices?skus=) 1분마다 상품 수만큼 요청이 나간다. 전체 수가 필요하면 서버 수(목록 수 PD-1 처럼)를 요청해야 한다.
- 확인: typecheck·lint·build 통과, test 622/623(카테고리 추가 1건은 전체 실행 때 시간 초과 — 따로 돌리면 5개 통과). 새 시험 4개. 화면 캡처(목록 띠·상세 다음 할 일).
